# services(Quarkus のマイクロサービス)

Quarkus REST、Java 21、PostgreSQL、Flyway、Hibernate ORM with Panache。
サービスは 3 つで、それぞれが自分のデータベースを持つ。

| サービス | 受け持つもの |
|---|---|
| `auth-service` | 登録、ログイン、セッション、パスワード。入口からのログインの確認に答える |
| `book-service` | レシピ帳、メンバー、招待。「誰がどのレシピ帳で何をできるか」の正本 |
| `kitchen-service` | レシピの編集内容、献立 |

仕事は、ログインの検証、権限の判定、入力値の検証、保存と取得に留める。
全体の図は [docs/architecture.html](../docs/architecture.html) にある。

## サービスの中の構成

機能ごとのパッケージの中を、入口(`*Resource`)、業務(`*Service`)、保存(`*Repository` と Entity)に分ける。
ほかのサービスを呼ぶ処理は `client` パッケージにまとめ、業務の処理から直接 HTTP を呼ばない。

```
src/main/java/app/recipebook/<サービス名>/
├── <機能>/        # 入口、業務、保存
├── client/        # ほかのサービスを呼ぶ処理
└── common/        # エラーの形、本人の特定、共通の設定
src/main/resources/db/migration/   # Flyway
src/test/java/
```

## サービスの間の決まり

- **ほかのサービスのデータベースを読まない。** 接続の設定も持たない。必要な情報は、持ち主のサービスの API から取る。
- **外に出す API は `/api`、サービスの間だけで使う API は `/internal` の下に置く。** `/internal` は入口から届かない。
- **ほかのサービスを呼ぶときは、期限を付ける。** 応答がないまま待ち続けない。
- **権限が確かめられないときは拒む。** `book-service` が応答しないときは 503 を返し、保存しない。
- **権限を自分で判断しない。** 役割は、必ず `book-service` に問い合わせた結果を使う。
- **ほかのサービスが持つ情報を、自分のデータベースに写さない。** 識別子だけを持つ。
- **本人は、要求に付いている署名付きトークンから特定する。** クッキーを読むのは `auth-service` だけである。
- **ほかのサービスを呼ぶときは、受け取ったトークンをそのまま渡す。**
- **サービスをまたぐ変更を 1 回の作業に混ぜない。** API を変えるときは、呼ばれる側を先に直し、呼ぶ側を後から直す。

## API の決まり

- **レシピ帳に関わる入口は、すべて役割を確かめてから処理する。** 確かめずにレシピ帳の識別子でデータを引かない。
- **メンバーでない人には 404 を返す。** 403 にしない。レシピ帳があることを知らせないためである。
- **役割が足りないメンバーには 403 を返す。**
- **入力は DTO で受け、Bean Validation で検証する。** Entity を入口の引数と戻り値に使わない。文字列と配列には長さの上限を付ける。
- **エラーは `{ code, message }` の形で返す。** どのサービスも同じ形にする。入口で個別に応答を組み立てない。
- **改訂番号が合わない保存は 409 を返し、保存しない。**
- **一覧を返すクエリには上限の件数を付ける。**
- **栄養計算を書かない。** ブラウザの仕事である。
- 日時は `Instant`、暦の上の一日は `LocalDate` で持つ。
- 入口を足すか変えたら、そのサービスの `api/<サービス名>.yaml` を出力し直す。

## 秘密の値の決まり

- **パスワードは bcrypt でハッシュにする。** セッションの識別子と招待リンクの文字列は、SHA-256 のハッシュだけを保存する。
- **パスワード、セッションの識別子、招待リンクの文字列、トークンをログに出さない。**
- **ログインの失敗は、メールアドレスの登録の有無で応答を変えない。**
- **署名の鍵とデータベースのパスワードをリポジトリに置かない。** Kubernetes の Secret から渡す。

## データベースの決まり

- **テーブルの変更は Flyway の新しいファイルで行う。** 適用済みのファイルを書き換えない。Hibernate にテーブルを作らせない。
- **データベースをまたぐ外部キーは張れない。** 参照先が消えたときの扱いを、そのサービスの中で決めて書く。

## テスト

- 入口ごとに、REST Assured で API のテストを書く。テストは本物の PostgreSQL に対して走らせる。
- ほかのサービスを呼ぶ箇所は、テストでは代役(モックのサーバー)に置き換える。代役には、正常な応答、404、応答なしの 3 通りを用意する。
- レシピ帳に関わる入口は、持ち主、編集できる人、見るだけの人、メンバーでない人、ログインしていない人の 5 通りについて、応答の状態をテストで確かめる。入口を足したら、この 5 通りを必ず足す。
- 受け入れ条件(要件定義の 4 章)のうち、API の応答に関わるものをテストにする。
- サービスをつないだ動きは、kind の上でブラウザのテストとして確かめる。
