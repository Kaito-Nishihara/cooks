# 0004 ログインの状態を、サーバー側のセッションとクッキーで持つ

決めた日: 2026-10-10

## 状況

ログインした後、「この人はログイン済みである」という状態を、どこにどう持つかを決める。
認証は自前で作るので、外部のサービスの仕組みには頼れない。

## 決めたこと

セッションを `auth-service` のデータベースに持ち、その識別子をクッキーでブラウザに渡す。
クッキーは、画面のスクリプトから読めない設定(`HttpOnly`)にする。

## 理由

- ログアウトとパスワードの変更で、セッションの行を消せば、次の要求からすぐに無効にできる。
- クッキーを `HttpOnly` にすると、画面に悪意のあるスクリプトを差し込まれても、識別子を読み取られない。
- ブラウザがクッキーを自動で付けるので、画面側で付け忘れが起きない。

## 却下した案

- **署名付きトークン(JWT)をブラウザの保存領域に置き、要求のたびにヘッダーで送る**: サーバー側に状態を持たずに済む。画面のスクリプトから読めるので、スクリプトを差し込まれると盗まれる。期限が来るまで無効にできず、ログアウトがすぐに効かない。
- **署名付きトークンをクッキーに入れ、サーバー側にセッションを持たない**: 盗まれにくさは同じになる。無効にできない点は変わらない。無効にするための一覧を持つと、結局サーバー側に状態を持つことになる。

## 影響

- 要求のたびに、`auth-service` がデータベースでセッションを確かめる。`auth-service` が止まると、ログインが要る操作がすべて止まる。
- クッキーを使うので、ほかのサイトから送られた要求を拒む対策(CSRF 対策)が要る。
- 画面と API を同じオリジンで配る必要がある。
