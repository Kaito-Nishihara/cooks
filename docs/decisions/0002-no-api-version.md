# 0002 API のパスに版の番号を入れない

決めた日: 2026-10-10

## 状況

API を後から変えるときに、古い呼び出し側を壊さないための仕組みを持つかどうかを決める。
よくある方法は、パスに `/v1` のような版の番号を入れ、互換性のない変更のたびに番号を上げることである。

## 決めたこと

パスに版の番号を入れない。
互換性のない変更をするときは、画面側の修正を同じ作業に含める。

## 理由

- API を呼ぶのは、同じリポジトリにある画面だけである。外部の利用者がいない。
- 画面とサービスを一緒に配置するので、古い画面が新しい API を呼ぶ期間がない。
- 画面側の型を仕様から生成するので、API を変えて画面を直し忘れると、型検査で止まる。

## 却下した案

- **最初から `/api/v1` にしておく**: 後から足すより楽に見えるが、番号を上げる場面が来ないまま、すべてのパスが長くなる。
- **ヘッダーで版を指定する**: 仕組みが増えるわりに、今の構成では使う場面がない。

## 影響

- サービスの間の API(`/internal`)は、呼ぶ側と呼ばれる側を別々に配置することがある。互換性のない変更は、呼ばれる側で新旧の両方を受け付ける期間を作り、呼ぶ側を直してから古いほうを消す。
- 外部に API を公開するか、画面とサービスを別々に配置するようになったら、この決定を見直す。
