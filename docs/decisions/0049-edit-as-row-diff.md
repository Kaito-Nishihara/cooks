# 0049 編集内容を、元のレシピとの行ごとの差分で持つ

決めた日: 2026-10-11

## 状況

利用者は、元のレシピの材料、手順、コツを直し、足し、消し、並べ替える(要件定義 4.5)。
編集内容は、元のレシピを書き換えずに、レシピ帳ごとに別に持つ。
元のレシピは、後から Claude Code が直すことがあり、そのときは編集内容を残したまま知らせる。

「データ設計」は、行に変わらない識別子を付けたうえで(決定の記録 0025)、編集内容を「行ごとの差分で持つか、直した後の全体で持つか」を、この機能の設計に回した。
編集内容は JSON の列に丸ごと入れ(「共通設計: データベースの共通仕様」の 5.5)、重ねる処理はブラウザで行う(要件定義 6 章)。

## 決めたこと

編集内容は、元のレシピとの差分を行ごとに持ち、直した行と足した行は行の全体を、消した行は識別子だけを、並びは変えたときだけ持つ。

形は「機能設計: レシピ帳とレシピの編集」の 5.3、重ねる決まりは 5.4 に書いた。

## 理由

- 直していない行が、元のレシピの更新に付いていく。利用者の編集の多くは、分量を 1 つか 2 つ変えるだけである。その人が、後から直された手順の誤字やコツを、何もしなくても受け取れる。
- 要件定義の「元のレシピに対する上書きとして別に持つ」「ブラウザ側で元のレシピへ重ねる」という書き方に、そのまま当てはまる。
- 直した行は行の全体を持つので、バックエンドが、元のレシピを知らないまま、1 行ずつ検証できる。「分量は、数と単位か、表記のどちらか一方」という決まりは、行の全体がないと確かめられない。
- 消した行の識別子を持つので、編集の画面で、消した行を一覧にして戻せる。
- 元のレシピが更新されたときの結果が、行ごとの決まり(直した行は自分のもの、直していない行は元のもの)で説明できる。

## 却下した案

- **直した後の全体を持つ**: 重ねる処理が要らず、画面の入力の形と API の形が同じになる。元のレシピが更新されても、編集したレシピには何も反映されない。分量を 1 つ変えただけの人が、その後の元のレシピの直しを、すべて受け取れなくなる。保存した時点の元のレシピを持っていないので、どの行を利用者が変えたのかを、後から知る方法もない。
- **直した後の全体と、保存した時点の元のレシピの写しを、両方持つ**: 利用者が変えた行を後から求められる。データベースに元のレシピの写しが入る。「元のレシピをデータベースに入れない」という決まりに反し、編集内容の大きさが倍になる。
- **項目ごとの差分を持つ(直した行の、変えた項目だけ)**: 分量だけを変えた行で、元のレシピが名前を直したときに、両方が生きる。行の一部しかないので、バックエンドが行を検証できない。「数と単位」を「表記」に変えた行で、元のレシピが単位を変えると、数と表記の両方を持つ行ができる。
- **操作の記録を持つ(「i1 を 300g にした」「i4 を消した」を順に並べる)**: 何をしたかが残る。同じ行を何度も直すと記録が増え続ける。丸ごと読んで丸ごと書く、という JSON の列を使う条件に合わない。

## 影響

- 画面の入力の形(重ねたレシピ)と、API の入力の形(差分)が違う。画面は、保存のたびに差分を作る。バックエンドが返した誤りの位置を、行の識別子を使って入力欄に割り当てる処理が要る。
- 重ねる処理と、差分を作る処理を、`frontend/src/domain/recipe/` に、React に頼らない関数として書く。端の場合が多いので、単体テストで確かめる(`AC-EDIT-30` から `AC-EDIT-48`)。
- 直した行は、行の全体が利用者のものになる。その行について、元のレシピの後からの直しは反映されない。
- 直した行が元のレシピから消えたときは、その変更を表示せず、画面で知らせる。次に保存した時点で、編集内容から除かれる。
- 元のレシピが、消した行の識別子を使い回すと、新しい行が「消した行」として隠れる。全体を持つ案では起きない。使い回しを禁じる決まり(決定の記録 0025)に頼る。
- 材料のグループを編集の対象にしないことを、この形の前提にしている。グループを編集できるようにするときは、この記録を見直す。
- P1 のレシピの複製は、元のレシピを持たないので、この形では持てない。複製の機能を設計するときに、別の持ち方を決める。
