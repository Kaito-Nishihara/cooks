# 0015 クラスタへ載せるのに Kustomize を使う

決めた日: 2026-10-11

## 状況

マニフェストをどう持ち、どの道具でクラスタへ載せるかを決める。
要件定義の未決事項「クラスタへ載せる道具」を、ここで決める。

## 決めたこと

マニフェストは、そのままの YAML で持ち、環境ごとの違いを Kustomize で重ねる。
イメージを作る、kind に載せる、マニフェストを渡す、の流れは、道具のコンテナの中のスクリプトにまとめる。

## 理由

- Kustomize は kubectl に入っている。足す道具がない。
- マニフェストが、そのままの YAML である。Kubernetes が実際に受け取る形を、読んで学べる。
- 環境ごとの違い(手元と、後で決める配置先)を、元のファイルを書き換えずに重ねられる。

## 却下した案

- **Helm で自分のアプリのひな型を作る**: 値を差し替える仕組みが強い。YAML の中にひな型の記法が混ざり、読みにくくなる。サービスが 4 つで、差し替える値が少ないので、仕組みに見合わない。入口の製品を入れるのには、製品が配っているものを使う。
- **Skaffold**: イメージの作成から載せるまでを 1 つのコマンドにし、変更を見張って自動で載せ直せる。試していない。スクリプトで足りるうちは足さない。載せ直しが遅くて困るようになったら、入れるかを決める。
- **Tilt**: Skaffold と同じ役目で、画面が付く。同じ理由で、今は足さない。

## 影響

- 載せ直しは、手でコマンドを打つ。自動では載せ直さない。
- スクリプトを自分で持つので、直すのも自分である。
- 載せ直しにかかる時間を、開発の土台を作るときに測る。長いときは、この決定を見直す。
