# 0028 成分表の「微量」を 0 として読む

決めた日: 2026-10-11

## 状況

成分表のセルには、数のほかに、`Tr`(微量)、`-`(測っていない)、括弧の付いた値が入っている。
要件定義 7.2 は、`-` と `Tr` を `null`、`(0)` と `0` を `0` として読むと決めていた。
取得した成分表のファイルで、使う 5 列(エネルギー、たんぱく質、脂質、炭水化物、食塩相当量)を数えると、`Tr` が 173 件、`(Tr)` が 6 件、`-` が 3 件、括弧の付いた数が 979 件あった。
`null` の成分を持つ食品は、栄養計算で「値が分からない」として扱い、「概算値」の印を付けることになる。
`Tr` をどちらに読むかで、「概算値」になるレシピの数が変わる。

## 決めたこと

`Tr` と `(Tr)` は `0`、括弧の付いた数は括弧を外した数、`-` だけを `null` として読む。

## 理由

- 微量の成分は、合計をほとんど変えない。分からない値として除いても、0 として足しても、表示する値は同じである。
- `null` として読むと、「概算値」の印が、意味のない場面で付く。例: 本みりんは脂質が `Tr` なので、みりんを使うレシピが、すべて「概算値」になる。印が多すぎると、調味料が丸ごと抜けているような、本当に気を付けるべき場面と区別できなくなる。
- 括弧の付いた数(推計した値)を使わないと、979 件の値を捨てることになる。推計した値を使うほうが、0 や `null` にするより実際に近い。
- `-` は 5 列で 3 件しかない。これを `null` のままにしても、「概算値」が増えすぎることはない。

## 却下した案

- **要件定義のとおり、`Tr` を `null` として読む**: 「測れていない」ことを正直に持てる。上の理由のとおり、「概算値」の印が役に立たなくなる。
- **`Tr` を `null` として持ち、栄養計算のときに 0 として扱う**: 変換した後のデータに、もとの記号の区別が残る。「`null` は除く」と「`null` でも `Tr` 由来なら足す」を区別するために、記号の種類を別の項目で持つことになる。その区別を使う機能がない。
- **`-` も 0 として読む**: `null` がなくなり、計算が単純になる。測っていない値を 0 と表示することになり、要件定義 4.3 の「正確そうに見える数値だけを出すのを避ける」に反する。

## 影響

- 要件定義 7.2 の記号の読み方を直す。
- `data/foods.json` の成分は、数か `null` のどちらかになる。もとの記号の種類(推計かどうか)は残らない。
- 表にない書き方のセルがあると、変換スクリプトは失敗する。
- 括弧の付いた書き方の正確な意味は、成分表の第 1 章で確かめていない。確かめた結果、この読み方が合わないと分かったときは、新しい決定の記録を足す。
