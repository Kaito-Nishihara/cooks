# 0011 サービスのビルドに Maven を使う

決めた日: 2026-10-11

## 状況

Quarkus のサービスをビルドする道具を決める。
Quarkus は、Maven と Gradle の両方に対応している。

## 決めたこと

Maven を使う。
`services/` の直下に親の `pom.xml` を置き、共通のライブラリと 3 つのサービスを、その下にまとめる。

## 理由

- Quarkus の公式の手引きは、Maven の例を先に載せている。調べたことを、そのまま使える。
- 設定が、決まった形の XML である。書き方の幅が狭く、3 つのサービスの設定をそろえやすい。
- 親の `pom.xml` の 1 か所で、Quarkus と拡張の版を決められる。

## 却下した案

- **Gradle**: ビルドが速く、設定を短く書ける。設定がプログラムなので、書き方の幅が広く、サービスごとに書き方がずれやすい。このアプリの大きさでは、速さの差が小さい見込みである。

## 影響

- Maven は、ホスト側に入れない。コンテナの中で動かす。
- 取ってきたライブラリを、コンテナを作り直すたびに取り直さないように、保存先を残す。方法は「共通設計: 実行環境」で決める。
