# 0031 招待の文字列を、URL のフラグメントで渡す

決めた日: 2026-10-11

## 状況

招待は、持ち主が作ったリンクを相手に渡し、相手がそれを開いて受ける(要件定義の 4.7)。
リンクに入る招待の文字列は、知っている人なら誰でも招待を受けられる秘密の値である。
データベースにはハッシュだけを保存し、サービスのログにも出さない(「共通設計: サービスの共通構成」の 4.5)。

招待の確認と参加の画面(`/invite`)は、ログインが要る。
ログインしていない人や、登録していない人がリンクを開くと、ログインの画面や登録の画面をはさむ。
その間、招待の文字列をどこに持つかを決める必要がある。
ログインが要る画面の枠は、元の画面のパスとクエリを、`/login` のクエリの `next` に入れて運ぶ(「共通設計: 画面の共通仕様」の 3.9)。

画面は静的に書き出すので、招待の文字列をパスに入れることはできない(決定の記録 0030)。

## 決めたこと

招待のリンクを `/invite#<招待の文字列>` とし、招待の文字列を URL のフラグメントで渡す。
ログインと登録をはさむ間も、`next` には入れず、移る先の URL のフラグメントとして持ち回る。

例: ログインしていない人が `/invite#abc` を開くと、`/login?next=%2Finvite#abc` へ移り、ログインすると `/invite#abc` に戻る。

## 理由

- フラグメントは、ブラウザがサーバーへ送らない。画面のファイルを取る要求にも、`Referer` ヘッダーにも入らないので、入口と、画面を配るコンテナの記録に残らない。
- 招待の文字列がサーバーへ送られるのは、招待の API(`/api/invitations/{token}`)を呼ぶときだけになる。記録から隠す場所を、この 1 つのパスの型に絞れる。
- ブラウザの保存領域を使わずに済む。「保存するのは、今開いているレシピ帳の識別子だけ」という決まりを保てる。
- リンクを開いたタブの中だけで流れが完結する。タブを閉じれば、画面が持っていた値はなくなる。
- `next` の確かめ方を変えずに済む。フラグメントは、確かめた後のパスの後ろに付けるだけである。

## 却下した案

- **クエリに入れる(`/invite?token=...`)**: 枠の決まり(パスとクエリを `next` に入れる)のままで、ログインをはさんで運べる。`/invite?token=...` と `/login?next=%2Finvite%3Ftoken%3D...` の両方がサーバーへ送られ、入口とコンテナの記録に、招待の文字列が残る。その画面から送る API の要求の `Referer` ヘッダーにも入る。
- **パスに入れる(`/invite/<招待の文字列>`)**: API のパスと形がそろう。静的な書き出しでは、ビルドのときに分からない値をパスに持てない。どのパスでも同じ HTML を返す設定が要り、記録に残る点はクエリと同じである。
- **最初に `sessionStorage` へ移し、URL からはすぐに消す**: アドレスの欄と履歴に残る時間が短い。保存したものを消す時点(参加した、やめた、使えなかった、途中でタブを離れた)を決める必要があり、消し忘れると残る。ログインしていない人には枠が画面の中身を描かないので、移す処理を枠より外に置くことになり、招待だけのための処理が全体の枠に入る。再読み込みや、別のタブで開き直したときの動きも、URL だけを見ては分からなくなる。
- **招待の画面だけ、ログインしていなくても内容を見せる**: ログインの前に、誰のどのレシピ帳への招待かが分かる。招待の内容を返す API をログインなしで呼べるようにする必要があり、招待の文字列を知った人が、レシピ帳の名前と持ち主の表示名を、アカウントなしで読める。要件定義の 8 章は、この API にログインを求めている。

## 影響

- ログインが要る画面の枠、ログインの画面、登録の画面は、URL のフラグメントを落とさずに引き継ぐ。「共通設計: 画面の共通仕様」の 3.9 に、この決まりを足した。
- ログインと登録をはさんでいる間は、アドレスの欄と、ブラウザの履歴に、招待の文字列が残る。参加に成功したとき、やめたとき、使えないと分かったときに、URL から取り除く。途中でやめた人の履歴には残るが、招待は 1 回しか使えず、7 日で切れる。
- 招待の文字列は、招待の API のパスには入る。入口の記録に、実際のパスをそのまま残さないことを、「共通設計: 実行環境」に頼む。この項目は、決定の記録 0056 で置き換えた。招待の文字列は、API のパスに入れず、本文で渡す。
- 画面は、招待の文字列を、保存領域、コンソール、タブの題、本文に出さない。受け入れ条件(`AC-NAV-35`、`AC-NAV-36`)で確かめる。
- 画面の失敗を外のサービスへ送って集める仕組みを入れるときは、URL のフラグメントを送らないようにする。今は入れていない(「共通設計: 画面の共通仕様」の 4.7)。
- メールを送る機能を足して、アプリが招待のリンクを送るようになったときは、メールの中のリンクの形として、この決定を見直す。
