# 0063 JSON のログに、Quarkiverse の拡張を使う

決めた日: 2026-10-12

## 状況

ログは、1 行に 1 件の JSON で出す(「共通設計: サービスの共通構成」の 4.6)。
`requestId`、`method`、`route`、`status`、`durationMs` は、`level` や `message` と同じ階層の項目として出す。
`status` と `durationMs` は、数として出す。
設計では、Quarkus の本体に付く拡張(`io.quarkus:quarkus-logging-json`)を使うとしていた。
この拡張は、要求ごとに付ける値を `mdc` という入れ子の中にだけ出し、値はすべて文字列になる。
同じ階層に出す設定がない。

## 決めたこと

Quarkiverse の拡張(`io.quarkiverse.loggingjson:quarkus-logging-json`)を使う。

## 理由

- 要求ごとに付ける値を、同じ階層に出す設定がある。
- ログを出すときに、名前と値の組を渡せる。値の型(数、文字列)が、そのまま JSON に出る。
- 項目の名前と、出す項目を、設定で選べる。
- Quarkus の 3.40.1 と組み合わせて、動くことを確かめた。

## 却下した案

- **Quarkus の本体に付く拡張を使い、`mdc` の入れ子のままにする**: 足すものがない。ログを探すときに、項目の場所が 2 通りになる。`status` を数として比べられない。
- **本体に付く拡張を使い、起動のときに出力の形を差し替える**: 足すものがない。Quarkus の内部の作りに頼るので、版を上げたときに黙って効かなくなるおそれがある。
- **Quarkus の拡張を自分で作る**: 形を自由に決められる。作るものが大きい(決定の記録 0009 で、共通のコードを拡張にしないと決めた)。

## 影響

- この拡張は、Quarkus の版の一覧(BOM)に入っていない。版を、親の `pom.xml` に固定する。
- Quarkus の版を上げるときに、この拡張が対応しているかを確かめる。対応が止まったときは、本体に付く拡張へ戻し、入れ子の形を受け入れるかを決め直す。
- 設定の名前は `quarkus.log.json` で始まる。本体に付く拡張の `quarkus.log.console.json` とは違う。
