# 0041 検索の語を、URL のクエリに残す

決めた日: 2026-10-11

## 状況

レシピ一覧は、検索の欄とジャンルで絞り込む。
選んだジャンルは、URL のクエリ(`genre`)に残すと決まっている(要件定義の 4.1、決定の記録 0030)。
検索の語を URL に残すかどうかは、決まっていなかった(「画面設計: 画面の一覧と遷移」の未決事項)。

今の静的なレシピ集は、検索の語を URL に残していない。
レシピのページは別の HTML なので、ブラウザの「戻る」で一覧に戻ると、ブラウザが検索の欄の中身を戻すことがある。
アプリでは、画面の間を、ページを読み込み直さずに移る。
検索の語を画面の中の状態としてだけ持つと、レシピ詳細から戻ったときに、検索の欄が空になる。

## 決めたこと

検索の欄に入れた文字列を、URL のクエリ `q` に残す。書き換えるときは、ブラウザの履歴に積まず、今の項目を置き換える。

例: ジャンル「副菜」を選び、「にんじん」と入れると、URL は `/?genre=副菜&q=にんじん` になる。

## 理由

- 検索して、レシピを 1 つ開き、「戻る」で一覧に戻る、という使い方が多い見込みである。戻るたびに語を入れ直させない。
- ジャンルと同じ持ち方になる。片方だけが URL に残ると、再読み込みしたときに、絞り込みの半分だけが残る。
- 検索の語は、秘密の値でも、個人の情報でもない。クエリに入れてよい値である(決定の記録 0030)。
- 履歴に積まないので、何文字入れても、「戻る」1 回で前の画面に戻れる。

## 却下した案

- **URL に残さず、画面の中の状態としてだけ持つ**: URL の決まりが増えない。レシピ詳細から戻ると、検索の欄が空になる。
- **`sessionStorage` に持つ**: URL が短いままで、戻ったときに語が残る。ブラウザに保存するのは、今開いているレシピ帳の識別子だけ、という決まり(「共通設計: 画面の共通仕様」の 5 章)を崩す。URL を人に渡しても、同じ絞り込みにならない。
- **1 文字ごとに履歴に積む**: 「戻る」で、1 文字前の状態に戻れる。一覧に来る前の画面に戻るのに、入れた文字の数だけ「戻る」を押すことになる。
- **正規化した後の文字列を残す**: 同じ検索が、同じ URL になる。再読み込みしたときに、検索の欄の中身が、入れた文字と変わる。例: 「ハンバーグ」と入れたのに、「はんばーぐ」と出る。

## 影響

- 画面が読むクエリは、`genre`、`q`(`/`)、`day`(`/menu`)、`next`(`/login`、`/register`)の 4 つになる。「画面設計: 画面の一覧と遷移」の 3.2 の表に `q` を足した。
- `q` は、利用者が書き換えられる。画面は、100 文字までを、文字として検索の欄に入れる。HTML として解釈しない。
- URL の書き換えは、入力が止まってから行う。1 文字ごとに書き換えると、ブラウザが、短い時間に多すぎる書き換えを拒むことがあるためである。待つ時間(0.3 秒)は見込みである。
- 静的な HTML は、クエリの値を知らずに作られる。`q` を付けて開くと、すべてのカードが一度見えてから、絞り込んだ結果に変わる。この見え方を許す(「機能設計: レシピ一覧と詳細」の 3.1)。
- 入口と、画面を配るコンテナの記録に、検索の語が残ることがある。秘密の値ではないので、許す。
