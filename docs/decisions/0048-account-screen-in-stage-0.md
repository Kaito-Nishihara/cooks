# 0048 アカウントの画面を、段階 0 で作る

決めた日: 2026-10-11

## 状況

「画面設計: 画面の一覧と遷移」が、アカウントの画面(`/account`)を足した。
パスワードを変える API(`PUT /api/me/password`)があるのに、それを呼ぶ画面がなかったためである。
パスワードを変える機能は、要件定義の 4.4 の受け入れ条件に含まれていないので、どの段階で作るかが決まっていなかった。
作るまでは、利用者のメニューに「アカウント」を出さないことになっていた。

## 決めたこと

アカウントの画面と `PUT /api/me/password` を、登録とログインと同じ段階 0(開発の土台)で作り、利用者のメニューの「アカウント」を段階 0 から出す。

## 理由

- パスワードの再設定がない間は、パスワードが漏れたと思った利用者にできることが、パスワードを変えることだけである。変えると、ほかの端末のセッションが切れる(「共通設計: 認証」の 4.9)。この手段を、登録ができる時点から用意する。
- 「共通設計: 認証」の受け入れ条件(`AC-AUTHN-20`)が、パスワードを変えたときのセッションの扱いを確かめる。この API は、`auth-service` を作る段階で要る。API だけを作って画面を後にすると、利用者には使えないまま残る。
- 画面は、文字を 2 つ出し、入力欄が 2 つあるフォームを 1 つ持つだけである。登録とログインの画面と同じ部品(入力欄、ボタン、通知)で作れる。
- 段階 0 は、ログインが要る画面の枠と、操作の途中で 401 になったときのダイアログを確かめる段階である。段階 0 には、ほかにログインが要る画面がない。アカウントの画面があると、枠とダイアログを、実際の画面で確かめられる。

## 却下した案

- **段階 3(レシピ帳とレシピの編集)で作る**: 段階 0 を小さく保てる。段階 0 から 2 の間に登録した利用者が、パスワードを変えられない。枠とダイアログを確かめる画面も、段階 3 までない。
- **段階 6(配置)で、パスワードの再設定と一緒に作る**: アカウントに関わる機能をまとめて作れる。本番に置くまで、パスワードを変える手段がない。
- **API だけを段階 0 で作り、画面は後にする**: `AC-AUTHN-20` は通る。画面のない API が残り、画面を作るときに初めて、文言と失敗の出し方の不具合に気づく。

## 影響

- 「画面設計: 画面の一覧と遷移」の 8 章の未決事項を、決まったこととして書き換えた。
- 段階 0 の終わりの条件(要件定義の 11 章)は、「4.4 の受け入れ条件が通る」のままである。「機能設計: 登録とログイン」の `AC-AUTH-39` から `AC-AUTH-46`、`AC-AUTH-64` から `AC-AUTH-68` も、段階 0 で通す。
- 表示名とメールアドレスの変更、アカウントの削除を足すときは、この画面に足す。
