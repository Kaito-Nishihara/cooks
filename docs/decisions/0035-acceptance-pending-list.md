# 0035 テストのない受け入れ条件を、「まだ作らない」の一覧で管理する

決めた日: 2026-10-11

## 状況

仕様書には、識別子の付いた受け入れ条件が数百ある。
実装は段階に分けて進むので、途中の時点では、テストのない条件が多く残る。
「まだ実装していないのでテストがない」と「実装したのにテストを書き忘れた」を、機械で見分ける方法を決める。

## 決めたこと

テストがなくてよい識別子を、1 つのファイル(`docs/acceptance-pending.txt`)に列挙する。
CI は、仕様書にある識別子のうち、テストにも一覧にもないものがあれば失敗する。
機能を実装する PR が、対応する識別子を一覧から消す。

## 理由

- 書き忘れが、PR の時点で分かる。
- 一覧の行数が、残っている仕事の量になる。空になれば、すべての条件にテストがある。
- 実装の PR の差分に「一覧から消した識別子」が出るので、その PR が何を満たしたかを、レビューで読める。
- 仕組みが、識別子を探すだけで済む。

## 却下した案

- **仕様書の表に、段階の列を足す**: 条件のそばに書けるので、読みやすい。すべての仕様書の表を直すことになり、「今どの段階まで終わったか」を別に持つ必要がある。
- **テストがなくても失敗させず、一覧を出すだけにする**: 仕組みがいちばん軽い。書き忘れに誰も気付かない。
- **すべての条件に、最初から「飛ばす」印の付いた空のテストを書く**: テストの側だけで完結する。数百の空のテストを先に書くことになり、条件を直すたびに 2 か所を直す。

## 影響

- 仕様書に条件を足す PR は、テストを書くか、一覧に足す必要がある。
- 一覧に足せば CI を通せるので、書き忘れを一覧に逃がすことができてしまう。一覧に行を足す PR では、理由を本文に書く。
- 識別子を探す道具は、テストの名前に識別子が文字どおり書かれていることに頼る。識別子を変数で組み立てない。
