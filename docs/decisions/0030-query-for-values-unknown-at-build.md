# 0030 ビルドのときに分からない値は、パスに入れずクエリで渡す

決めた日: 2026-10-11

## 状況

画面は静的に書き出す(要件定義の 6 章)。
静的な書き出しでは、ビルドのときに HTML のファイルを作れるパスしか持てない。
元のレシピの slug は、ビルドのときに `data/recipes/` を読めば分かる。
献立の日付と、一覧で選んだジャンルは、利用者が開くまで分からない。
これらの値を、URL のどこに入れるかを決める。
秘密の値である招待の文字列は、別に決める(決定の記録 0031)。

## 決めたこと

ビルドのときに分かる値(slug)はパスに入れ、ビルドのときに分からない秘密でない値(献立の日付、ジャンル、ログインの後に移る先)はクエリに入れる。

例: レシピ詳細は `/recipes/oyakodon`、10 月 12 日の献立は `/menu?day=2026-10-12` とする。

## 理由

- ビルドで作ったファイルと、パスが 1 対 1 に対応する。画面を配るコンテナは、パスに合うファイルを返すだけでよい。
- ないパスに、HTTP の状態 404 をそのまま返せる。URL を打ち間違えた人が、間違いに気づける。
- 値が URL に残るので、再読み込みしても、URL を人に渡しても、同じ日の献立が出る。
- 入口の設定に、画面のパスの一覧を持たずに済む。画面を足しても、入口を直さなくてよい。
- 要件定義の 10 章のパス(`/menu`)を変えずに済む。

## 却下した案

- **パスに入れ(`/menu/2026-10-12`)、どのパスで来ても同じ HTML を返すように配る**: URL の見た目がそろう。コンテナに、ないパスでも HTML を返す設定(フォールバック)が要る。ないパスにも 200 が返るので、見つからないページを状態 404 で返せなくなる。パスが正しいかどうかを、ブラウザの中の処理で判定し直すことになる。
- **パスに入れ、あり得る日付のページをすべてビルドで作る**: フォールバックが要らない。日付は終わりがなく、作る範囲を決めても、その外の日が開けない。ビルドのたびにファイルが増える。
- **URL に入れず、画面の中の状態としてだけ持つ**: URL の決まりが要らない。再読み込みすると今日に戻る。ログインの画面をはさんだときに、見ていた日を `next` で運べない。
- **フラグメントに入れる(`/menu#2026-10-12`)**: クエリと同じく、ファイルは 1 つで済む。フラグメントは、ページの中の位置を指すのが本来の使い方で、「本文へ移動」のようなページの中のリンクと混ざる。サーバーへ送られないことが利点になるのは、秘密の値だけである。

## 影響

- 画面が読むクエリは、`genre`(`/`)、`day`(`/menu`)、`next`(`/login`、`/register`)の 3 つである。足すときは、「画面設計: 画面の一覧と遷移」の 3.2 の表に足す。
- クエリの値は利用者が書き換えられるので、画面は形を確かめてから使う。
- クエリはサーバーへ送られ、記録に残ることがある。秘密の値と個人の情報を入れない。
- 静的な HTML はクエリの値を知らずに作られるので、クエリで変わる部分は、ブラウザの中の処理が動いてから決まる。
- 画面を配るコンテナに、フォールバックを入れない。「共通設計: 実行環境」で、この前提を満たせるかを確かめる。
- P1 のレシピの複製のように、ビルドのときに分からない識別子を持つ画面が増えたら、この決まりに従ってクエリに入れる。パスに入れる必要が出てきたら、見直す。
