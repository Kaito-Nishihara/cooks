# 0014 kind、kubectl、helm をコンテナの中で動かす

決めた日: 2026-10-11

## 状況

手元の Kubernetes を扱うには、kind、kubectl、helm が要る。
これらを、どこに入れるかを決める。

## 決めたこと

道具を入れたコンテナを用意し、その中で動かす。
ホスト側に入れるのは、Docker だけとする。

## 理由

- Node と Java をホスト側に入れない、という決まりと、そろう。
- 道具の版を、リポジトリの `Dockerfile` に固定できる。機械ごとに版が違って動きが変わる、ということが起きない。
- ホスト側のシェルの種類(PowerShell、Bash)に左右されない。
- この動かし方で、クラスタの作成、マニフェストの適用、helm での導入ができることを、試作で確かめた。

## 却下した案

- **ホスト側に入れる**: 手引きの多くが、この形で書かれている。コマンドが短い。入れる手順が機械ごとに違い、版がそろわない。
- **Docker Desktop に付いている Kubernetes を使う**: 入れるものがない。クラスタを作り直すのに手間がかかり、構成をファイルで固定できない。要件定義は kind を使うと決めている。

## 影響

- コマンドが長くなる。短い呼び名のスクリプトを用意する。
- 道具のコンテナに、Docker のソケットを載せる。コンテナの中から、ホスト側の Docker を操作できる。手元の開発用であり、配置する環境では使わない。
- クラスタには、クラスタの中の住所で届く。そのために、道具のコンテナを kind のネットワークにつなぐ。
