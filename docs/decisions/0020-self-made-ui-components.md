# 0020 画面の部品を自分で作り、外の部品集を入れない

決めた日: 2026-10-11

## 状況

ボタン、入力欄、ダイアログ、通知のような、どの画面でも使う部品を、どう用意するかを決める。
見た目は、静的レシピ集(`recipes/assets/recipe.css`)の色、書体、部品を引き継ぐ(要件定義の 10 章)。
キーボードだけで操作できることも求められている(要件定義の 5 章)。

## 決めたこと

共通の部品は、HTML の標準の要素(`<button>`、`<select>`、`<dialog>` など)と Tailwind のクラスで自分で作り、`src/components/ui/` に置く。

## 理由

- 引き継ぐ見た目が、すでに決まっている。部品集の見た目を打ち消して合わせるより、最初から書くほうが、書く量も、後で読む量も少ない。
- 要る部品は 20 個ほどで、動きが込み入ったものはダイアログと通知だけである。ダイアログは、`<dialog>` の `showModal()` が、フォーカスを中に閉じ込める動きと Esc キーで閉じる動きを受け持つ。
- 標準の要素は、キーボードの操作と、読み上げソフトへの伝わり方が、最初から備わっている。レシピ帳の切り替えを `<select>` にするのは、このためである。
- 頼る部品が少ないと、Next.js や React の版を上げるときに、合わせて直すものが減る。

## 却下した案

- **見た目を持つ部品集(MUI など)を入れる**: すぐに使える部品が多い。見た目が部品集のもので決まっていて、和紙の色合いと丸い書体に合わせるには、ほぼすべてを上書きすることになる。
- **見た目を持たない部品集(Radix UI、Headless UI など)を入れる**: 動きとキーボードの操作だけを受け持ち、見た目は自分で付けられる。込み入った部品(絞り込みながら選ぶ欄、入れ子のメニュー)を作るときには助かる。今の画面の一覧には、標準の要素で足りない部品がない。

## 影響

- アクセシビリティは、部品集に任せられないので、自分で確かめる。ブラウザのテストで axe の検査を走らせ、キーボードだけで操作するテストを書く(「共通設計: 画面の共通仕様」の 3.11)。
- 標準の要素で作れない部品が出てきたときに見直す。見込みでは、レシピの編集で、食材マスタから絞り込みながら選ぶ欄がそれに当たる。そのときは、見た目を持たない部品集を、その部品にだけ使うことを考え、新しい決定の記録を書く。
- `<dialog>` と `showModal()` が、テストに使うブラウザで決まりどおりに動くことは、開発の土台を作るときに確かめる。
