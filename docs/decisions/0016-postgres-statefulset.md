# 0016 手元のクラスタでは PostgreSQL を 1 つの Pod で動かす

決めた日: 2026-10-11

## 状況

クラスタの中での PostgreSQL の置き方を決める。
サーバーを 1 つにすることは、決定の記録 0007 で決めてある。

## 決めたこと

公式のイメージを、1 つの Pod で動かす。
再起動しても同じ保存先につながる種類(StatefulSet)にする。
最初の起動のときに、3 つのデータベースと 3 つの接続する利用者を作る。

## 理由

- 手元で要るのは、動くことと、作り直せることだけである。
- マニフェストが短く、何が起きているかを読める。
- データベースと利用者の作り方が、Compose と同じ初期化のスクリプトで済む。

## 却下した案

- **PostgreSQL を管理する仕組み(オペレーター)を入れる**: 複製、切り替え、バックアップまで受け持つ。配置する場所では有力な選び方である。入れるものが増え、手元の機械が重くなる。手元では、その機能を使わない。
- **クラスタの外(Compose)で動かし、クラスタからつなぐ**: クラスタを消してもデータが残る。クラスタの中から外へつなぐ設定が要り、配置する環境と形が離れる。

## 影響

- 複製がない。Pod が止まると、3 つのサービスがすべて止まる。
- バックアップがない。クラスタを消すと、データも消える。
- 配置する場所を決めるときに、オペレーターか、その場所が用意するデータベースのサービスを選び直す。
