# 0055 今日でない日の献立には、献立の画面の中で料理を足す

決めた日: 2026-10-11

## 状況

レシピ一覧とレシピ詳細の「献立に追加」は、今日の献立に、押した時刻に合う食事として料理を足す(要件定義の 4.6)。
献立は日付ごとに保存し、日付を移してほかの日を見られる。
`/menu?day=2026-10-12` を見ている人が、その日に料理を足す入口を、「画面設計: 画面の一覧と遷移」は決めずに、この機能の設計に回していた。

## 決めたこと

献立の画面に「料理を足す」のボタンを置き、料理を選ぶダイアログを開く。
ダイアログで食事を選び、料理を探して、見ている日の献立に足す。
今日の献立にも、同じ入口を出す。
レシピ一覧とレシピ詳細の「献立に追加」は、今日の献立に足すままにする。

## 理由

- 足す先の日が、見ている画面そのものなので、どの日に入るかを取り違えない。
- 画面を移らないので、足す先の日を、URL やブラウザの保存領域で持ち回らずに済む。
- ほかの日では、押した時刻と食べる食事に関わりがない。ダイアログで食事を選ぶ形にすれば、時刻で決める必要がない。
- 今日の献立でも、朝のうちに夕食を決めるときに、食事を選んで足せる。今日とほかの日で入口を変えないので、画面の状態が 1 つ減る。
- 料理の名前と写真の場所は、献立の画面がすでに持っている。絞り込みは、レシピ一覧の検索の処理を使えるので、新しい検索を書かない。

## 却下した案

- **レシピ一覧へ日付を渡す(`/?day=2026-10-12`)**: 写真の並ぶ一覧から選べる。一覧とレシピ詳細の間のすべてのリンクに `day` を付けて回る必要があり、付け忘れると、今日の献立に入る。一覧のクエリが増え、「献立に追加」の文言と食事の決め方が、`day` の有無で変わる。
- **足す先の日を、ブラウザの保存領域に覚える**: URL を変えずに済む。別のタブや、後で開いた一覧でも、覚えた日に入り続ける。利用者から、どの日に入るかが見えない。
- **ほかの日には足せないことにし、今日の献立を写す機能を置く**: 入口が増えない。要件定義にない機能を足すことになり、明日の献立を前もって作れない。
- **今日でない日にだけ、ダイアログの入口を出す**: 今日の動きが、今の静的なレシピ集と同じになる。同じ画面なのに、日によって操作が変わる。

## 影響

- 「画面設計: 画面の一覧と遷移」の 3.3、3.4、3.8 と 8 章を直した。骨組みの「献立の画面には、料理を選ぶ欄を置かない」という決まりを、この決定で置き換えた。
- 要件定義の 4.6 に、献立のページでも料理を足せることを書き足した。
- 空の献立に出す「レシピを探す」のリンクは、今日を見ているときだけにした。レシピ一覧の「献立に追加」は今日に足すので、ほかの日を見ている人を一覧へ送ると、見ていた日と違う日に料理が入るためである。
- 献立の画面は、ダイアログの絞り込みのために、レシピの要約の一覧も読み込む(「データ設計」の 5.7)。
- 写真を見ながら、ほかの日の献立を選びたいという要望が出たら、ダイアログの一覧に写真を足すことから見直す。
