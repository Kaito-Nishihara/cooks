# 0024 今開いているレシピ帳を、ブラウザの localStorage に持つ

決めた日: 2026-10-11

## 状況

利用者は複数のレシピ帳に参加でき、画面の上部で、今開いているレシピ帳を切り替える(要件定義の 3 章)。
編集内容と献立の API は、パスにレシピ帳の識別子を取る(`/api/books/{bookId}/...`)。
画面のパスは `/menu`、`/recipes/[slug]/edit` のように、レシピ帳の識別子を含まない(要件定義の 10 章)。
「今どのレシピ帳を開いているか」を、どこに持つかを決める。

## 決めたこと

今開いているレシピ帳の識別子を、ブラウザの `localStorage` に `rb.currentBookId` という名前で持つ。
ページを開いたときに、`GET /api/books` の一覧と突き合わせ、一覧になければ自分のレシピ帳を開く。

## 理由

- 再読み込みしても、ブラウザを開き直しても、同じレシピ帳が開く。
- 要件定義の画面のパスを変えずに済む。
- 画面は静的に書き出すので、パスにレシピ帳の識別子を入れることができない。識別子は利用者ごとに違い、ビルドのときには分からないためである。
- レシピの URL(`/recipes/oyakodon`)を、レシピ帳によらず 1 つに保てる。ログインしていない人にも、同じ URL を渡せる。
- 識別子は秘密の値ではなく、権限の根拠にもならない。書き換えて他人の識別子を入れても、API が 404 を返す。

## 却下した案

- **URL のクエリに持つ(`/menu?book=<識別子>`)**: URL を渡せば、相手が同じレシピ帳を開ける。タブごとに別のレシピ帳を開ける。すべてのリンクにクエリを付けて回る必要があり、付け忘れると、移った先で別のレシピ帳に変わる。レシピ帳はメンバーにしか見えないので、URL を渡して開ける相手も限られる。
- **バックエンドに持つ(利用者ごとに「最後に開いたレシピ帳」を保存する)**: 端末を替えても同じレシピ帳が開く。テーブルと API が増える。端末ごとに違うレシピ帳を開いておく使い方ができなくなる。
- **どこにも保存せず、ページを開くたびに自分のレシピ帳を開く**: 保存するものがない。招待されたレシピ帳を主に使う人が、再読み込みのたびに切り替え直すことになる。

## 影響

- 端末やブラウザを替えると、最初は自分のレシピ帳が開く。
- 同じブラウザの複数のタブは、開いた時点の値で動く。片方のタブで切り替えても、もう片方のタブは、再読み込みするまで前のレシピ帳のままである。それぞれのタブの API の呼び出しは、そのタブが開いているレシピ帳に対して行うので、保存先が入れ替わることはない。
- ログアウトのときに値を消す。同じブラウザを次に使う人に、前の人のレシピ帳の識別子を残さないためである。
- URL を渡して特定のレシピ帳を開かせる必要が出てきたら、見直す。
