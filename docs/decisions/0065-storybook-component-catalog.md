# 0065 部品と色の見本帳に Storybook を使う

決めた日: 2026-11-02

## 状況

画面の共通の部品(「共通設計: 画面の共通仕様」の 3.6)は、ふつう、使えない、処理中、エラーがある、のように状態が多い。
色、書体、余白の値(3.1 から 3.4)も、画面に組み込まれた形でしか見られない。
部品を作る人とレビューする人が、API やログインの状態を用意せずに、部品を状態ごとに見られる場所が要る。
その場所に、何を使うかを決める。

## 決めたこと

`frontend/` に Storybook を入れ、共通の部品と、色、書体、余白の値を並べた見本帳を作り、GitHub Pages で公開する。

## 理由

- React の部品を、状態ごとに切り離して見る道具として、広く使われている。このプロジェクトは、標準的なやり方を経験することを目的の 1 つにしている。
- 部品に渡す値(`props`)だけで状態を作れる。API、ログイン、レシピ帳を用意しなくても、エラーや処理中の見た目を確かめられる。
- 書き出したものは静的なファイルなので、レシピ集と同じ GitHub Pages で配れる。サーバーを持たない、という画面の決まりとも合う。
- 部品集ではなく、開発の道具である。アプリの書き出しには入らないので、決定の記録 0020(外の部品集を入れない)と食い違わない。

## 却下した案

- **見本のページを自分で書く(`docs/mockups/` と同じ形)**: 道具が増えない。部品を変えるたびに、見本のページも手で直すことになり、実物とずれる。
- **Ladle、Histoire のような軽い道具**: 起動が速い。使う人が少なく、経験として得るものが Storybook より少ない。
- **見本帳を作らず、Playwright のテストだけにする**: 道具が増えない。状態ごとの見た目を、人が見て確かめる場所がない。

## 影響

- `frontend/` の開発の依存に、Storybook が加わる。版を上げる手間が増える。
- 共通の部品を足すときに、見本(`*.stories.tsx`)も書く。
- GitHub Pages の公開に、Storybook の書き出しが加わる。レシピ集は今の住所のまま変わらない。
- 部品の数が増えず、見本帳を誰も見ていないと分かったときに、やめることを考える。
