# 0047 登録済みのメールアドレスを、`EMAIL_TAKEN` で知らせる

決めた日: 2026-10-11

## 状況

ログインの API は、パスワードが違うときと、メールアドレスが登録されていないときとで、同じ応答を返す。
メールアドレスが登録されているかを、外から調べられないようにするためである(要件定義の 4.4)。

登録の API は、登録済みのメールアドレスを拒む。
要件定義の 4.4 の受け入れ条件と、「共通設計: API の共通仕様」の 4.9 は、これを 409 と `EMAIL_TAKEN` で返すと決めている。
この応答からは、そのメールアドレスが登録済みであることが分かる。
ログインで隠していることを、登録では隠していないので、この食い違いを受け入れるかどうかを決める必要があった。

## 決めたこと

登録の API は、登録済みのメールアドレスに 409 と `EMAIL_TAKEN` を返し、画面はメールアドレスの欄の下に「このメールアドレスは、すでに登録されています。」と出す。

## 理由

- 登録の有無を隠すには、どのメールアドレスにも同じ応答を返し、結果をメールで本人にだけ知らせる必要がある。このアプリは、今の段階でメールを送らない(要件定義の 2.2)。
- 隠したまま画面に何も伝えないと、登録済みの人が同じメールアドレスでもう一度登録しようとしたときに、なぜ進めないのかが分からない。パスワードの再設定もないので、その人は行き詰まる。
- 登録済みと分かっても、ログインには 12 文字以上のパスワードが要る。失敗が 5 回続くと、15 分間受け付けない(「共通設計: 認証」の 4.4)。
- 保存している個人の情報は、メールアドレス、表示名、パスワードのハッシュだけである。登録済みと知られて分かるのは、その人がこのアプリを使っていることまでである。

## 却下した案

- **どのメールアドレスにも 201 を返し、登録済みのときは何も作らない**: 応答からは登録の有無が分からない。登録済みの人は、登録できたように見えるのにログインできない。新しく登録した人と区別するには、応答の後の動き(クッキーの有無)を変えることになり、結局そこから分かる。
- **「登録できませんでした」とだけ返す**: 文言からは理由が分からない。登録が失敗する理由がほかにないので、失敗したこと自体が登録済みを意味する。隠せていないうえ、利用者には不親切になる。
- **メールアドレスの確認を先に作り、確認のメールで知らせる**: 隠す方法として正しい。メールの送信手段は、配置する場所と一緒に決める(要件定義の 12 章)。それまで登録の機能を作れなくなる。
- **登録の API にも、メールアドレスごとの失敗の制限をかける**: 同じメールアドレスを調べるのは 1 回で足りるので、メールアドレスごとの制限は効かない。効くのは送り元ごとの制限で、これは配置を決めるときに決める(「共通設計: 認証」の 8 章)。

## 影響

この決定で、次の危険を受け入れる。

- ある人のメールアドレスを知っている他人が、その人がこのアプリを使っているかどうかを調べられる。
- 登録済みのメールアドレスを集めて、パスワードを当てる試みの的にできる。
- 登録の API に回数の制限がないので、調べる数に上限がない。

変わることと、見直す条件は次のとおりである。

- 「機能設計: 登録とログイン」の 4.3 に、危険と理由を書いた。
- 送り元ごとの制限を決めるとき(段階 6)に、登録の API も対象に入れる。
- メールを送れるようになったら、この決定を見直す。そのときは、登録の応答をどのメールアドレスでも同じにし、登録済みの人には「すでに登録されています」というメールを送る形にする。`EMAIL_TAKEN` を返さなくなるので、要件定義の 4.4 の受け入れ条件と、「共通設計: API の共通仕様」の 4.9 も直す。
