# 0008 行を消すときは、実際に消す

決めた日: 2026-10-11

## 状況

利用者が何かを消したときに、データベースの行をどう扱うかを決める。
方法は 2 つある。
行を実際に消す方法と、「消した」という印の列を持って行を残す方法(論理削除)である。

## 決めたこと

行を実際に消す。
論理削除は使わない。

## 理由

- 論理削除では、すべての検索に「消していないもの」という条件が要る。1 か所でも足し忘れると、消したはずのものが見える。権限の判定で足し忘れると、外されたメンバーがレシピ帳を読めてしまう。
- 「メールアドレスは重複を許さない」のような一意の制約が、消した行にも効いてしまう。退会した人が、同じメールアドレスで登録し直せなくなる。
- 個人の情報を、消した後も持ち続けることになる。

## 却下した案

- **すべてのテーブルに「消した日時」の列を持つ**: 誤って消したものを戻せる。上の 3 つの弱点がある。このアプリで消されるのは、編集内容、献立、メンバー、招待であり、戻せないと困るものは少ない。編集内容は「元に戻す」の前に確認を出す。
- **消した行を、別の履歴用のテーブルへ移す**: 検索の条件は要らなくなる。テーブルが 2 倍になり、移す処理を書くことになる。戻す機能を作る予定がない。

## 影響

- 消したものは戻せない。画面は、消す前に確認を出す。
- 「取り消した」「使った」のように状態が変わるものは、消さずに、その日時の列を持つ。招待がこれに当たる。
- 「誰がいつ消したか」は、データベースに残らない。必要になったら、操作の記録を別に持つ。
