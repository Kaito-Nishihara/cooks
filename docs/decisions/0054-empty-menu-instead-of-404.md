# 0054 まだ保存されていない日の献立は、404 ではなく空の献立を返す

決めた日: 2026-10-11

## 状況

「共通設計: API の共通仕様」の 4.10 は、改訂番号を持つもの(レシピの編集内容と献立)について、まだ保存されていないものを取得したときに 404 を返すと決めていた。
一方、メンバーでない人がレシピ帳の識別子を指定したときも、404 と `NOT_FOUND` を返す(要件定義の 4.7)。
献立は日付ごとにあり、献立の画面は、日を移すたびにその日の献立を取得する。
ほとんどの日は、まだ献立が保存されていない。

## 決めたこと

`GET /api/books/{bookId}/menus/{day}` は、まだ保存されていない日について、200 と、改訂番号が `0` の空の献立を返す。
献立の取得が 404 を返すのは、レシピ帳がないときと、メンバーでないときだけにする。

## 理由

- 画面が、「まだ献立がない」と「メンバーから外された」を、応答だけで見分けられる。404 を両方に使うと、外された人の画面が、空の献立を出し続ける。見るだけの人は保存をしないので、外されたことに気づく時点がない。
- 献立の画面では、保存されていない日を開くのがふつうの場合である。ふつうの場合にエラーの状態を返すと、ブラウザのコンソールとサービスのログに、失敗でない 404 が並ぶ。
- 「その日の献立」は、保存されていなくても、空のものとして意味がある。料理が 0 品の日である。
- 改訂番号 `0` は、すでに「まだ保存されていない」を表す値として、保存の要求で使っている(「共通設計: API の共通仕様」の 4.10)。取得の応答でも同じ意味で使える。

## 却下した案

- **共通の決まりのとおり 404 を返す**: レシピの編集内容と同じ動きになる。上の 2 つの場合を見分けるために、画面は 404 のたびにレシピ帳の一覧を取り直すことになる。
- **404 のままにし、`code` を分ける(例: `MENU_NOT_SAVED`)**: 状態は共通の決まりのとおりになる。`code` の一覧に、献立だけの値が増える。ふつうの場合にエラーを返す点は変わらない。
- **献立を開いたときに、空の行を作る**: 取得がいつも行を返す。`GET` が状態を変えることになり、開いただけの日の行が増え続ける。

## 影響

- 「共通設計: API の共通仕様」の 4.10 と、「共通設計: 画面の共通仕様」の 4.1 に、献立は例外であることを書き足した。
- 要件定義の 8 章の、献立の取得の説明に、空の献立を返すことを書き足した。
- レシピの編集内容の取得は、共通の決まりのとおり 404 を返す。編集内容は、編集済みのレシピの一覧で、あるかどうかが先に分かるためである。
- 画面の取得の関数(`getMenu`)は、404 を `null` に変えない。404 は、ほかの API と同じに、レシピ帳の一覧の取り直しにつなげる(「共通設計: 画面の共通仕様」の 3.10)。
