# PR 本文の規約

Claude が本リポジトリで PR を作成、更新するときの分量と体裁のルール。
タイトルは 70 文字以内の Conventional Commits 形式とし、draft で作成し、日本語で書く。
読者は merge 可否を判断するレビュアーであり、PR 本文は作業ログの置き場ではない。

## 構成

本文は上から次の順で書く。

1. **概要**: 何を、なぜ変えたか(箇条書き)
2. **要承認の決定事項**: レビュアーの可否判断が要る項目だけを書く。1 項目につき、選んだ案と却下した代替案とその理由を 1 行ずつ併記する。無いときも「特になし」と書く
3. **レビューの見どころ**: 判断が割れそうな箇所、自信の低い箇所、設計上のトレードオフを 1〜3 行で書く。無いときも「特になし」と書く。3 行に収まらないときは PR の分割を検討する
4. **確認手順**: レビュアーが再現できる手順のチェックリスト
5. **証跡**: テスト出力や検証記録。`<details>` の折りたたみに入れる

「要承認の決定事項」はレビュアーの返答を要する項目、「レビューの見どころ」は目を通してほしい項目である。

## 分量

- 折りたたみ部分を除き 1,500 字程度までとする。
- CI の画面で見える情報(check の結果、カバレッジ等)を本文に再掲しない。
- 差分を読めばわかる変更の列挙を書かない。意図だけを書く。
