# 日本語文章規範

Claude が本リポジトリで生成する日本語の文章に適用する。
対象は Issue と PR の本文とコメント、`docs/` 配下の文書、コード中のコメント、ユーザーへの応答である。
`~/.claude/rules/japanese-tech-writing.md` の最小規範を project に vendoring したもので、こちらが優先する。

## 整形

- 一文ごとに改行する。段落の区切りは空行で示す。
- 用語とその定義を並べる箇条書きは、全角コロンで「**用語**: 説明」と書く。
- 日本語の並列に中黒を使わない。ただし単一の固有名詞の内部では使ってよい。
- 日本語の地の文と見出しに em ダッシュを使わない。同格の補足は括弧に入れ、言い換えは句点か読点でつなぐ。
- 本文中の太字強調は論理の要所に限り、一節に一、二箇所までとする。
- 箇条書きと表は、並列の項目や同型の行を列挙するときに使う。説明はセルに詰めず地の文に書く。

## 表現

- LLM口調(「重要なのは~」「まとめると」「不可欠」「掘り下げる」「~の観点から」など)を使わない。主張はそのまま書く。
- 比喩や装飾で直接的な記述を置き換えない。「効いてくるパラメータ」ではなく「変えると結果が変わるパラメータ」と書く。字義どおりの表現があるならそれを使う。
- 気取った文(mannered prose)を書かない。比喩や飾りは書き手を見せるためのもので、読み手の負担を増やし、書き手が選んでいない含意を持ち込む。
- 同じ主張を言い換えて繰り返さない。描写の直後に要約し直さない。
- 検出や保証を「必ず」と書かず、成り立つ条件を付けて述べる。
- 確認していないことを確認したかのように書かない。推量は推量のまま残す。

## 引用

- 取得した Issue / PR / Slack / 議事録を要約するときは自分の言葉で言い換える。
- 原文の語句を残すときは「」で囲み、引用だと分かるようにする。1箇所程度に留める。
- 具体例は `.claude/skills/sprint-ceremony/review.md` の「デモ項目の整理」を参照。
