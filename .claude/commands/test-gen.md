# test-gen - テスト生成専門エージェント

対象: **$ARGUMENTS**(例: `recipe`、`ingredient`、`suggestion`、`menu`、`shopping`、`auth`)

あなたはテスト生成専門のエージェントです。
指定された対象のテストを生成し、実行してください。

> `/implement` を使った場合はテストも自動生成されます。このコマンドは既存実装へ後からテストを追加する際に使います。

## 前提

- 単体テスト: Vitest。ソースと同じディレクトリに `*.test.ts` として置く
- E2E: Playwright。`e2e/` に置く
- 実行: `docker compose exec app npm run test -- <パターン>`
- 規約: コメントは日本語、`any` 禁止、明示的な型定義

## ステップ1: 読み込み

次をすべて読んでから設計してください。

- `src/domain/<対象>/` の業務ロジック
- `src/shared/<対象>.ts` の Zod スキーマ
- `src/server/routes/<対象>.ts` と `src/server/db/queries/<対象>.ts`
- 既存のテストが一つでもあれば、その書き方を踏襲する

## ステップ2: テストケースの設計

ドメインサービスの公開メソッドごとに、次を列挙してください。

- 正常系: 代表的な入力と期待される戻り値
- 異常系: `NotFoundError`、`ConflictError`、`ValidationError` を投げる条件
- 境界値: 空配列、0 件、最大件数、null 許容フィールドの未設定

栄養値の算出(`nutrition`)は次を必ず含めてください。

- 自由記述の分量(「少々」)が計算から除外されること
- 単位換算率が未登録の材料が除外されること
- 代表食品番号が未設定の食材が除外されること
- 除外があった場合に、除外した材料が結果に列挙されること
- 計算できた材料が一つもない場合に、数値を返さず未算出を表すこと

レシピ提案(`suggestion`)は次を必ず含めてください。

- `ALLERGY` の食材を必須材料に含むレシピが候補から除外されること
- `HATE` の食材が既定で除外され、切り替えで表示できること
- 任意材料に該当する場合は除外されないこと
- スコアの加減算(`LOVE` +3、`LIKE` +1、`DISLIKE` -2)が正しいこと
- 直近 14 日の調理ログによる減点が働くこと

## ステップ3: 実装

- `src/domain/` は依存のない関数なので、モックなしで素のまま試す
- クエリは D1 のローカルエミュレーションに対して試す。Drizzle をモックしない
- テスト名は日本語で、条件と期待結果がわかるように書く(例: `アレルギー食材を含むレシピは候補から除外される`)
- `describe` はメソッド単位、`it` はケース単位で分ける

## ステップ4: 実行と報告

```bash
docker compose exec app npm run test -- <対象>
```

通過数、失敗内容、カバーできていない分岐を報告してください。
失敗を残したまま完了としないでください。実装側の不具合を見つけた場合は、テストを実装に合わせず、不具合として報告してください。
