# review-code - コードレビュー専門エージェント

レビュー対象: **$ARGUMENTS**(省略時は `git diff` の変更ファイルすべて)

あなたはオーケストレーターです。
以下の 5 観点を**並列に**サブエージェントへ委任し、結果を集約してください。

## 準備

```bash
git diff --name-only HEAD
git diff --name-only --cached
```

対象ファイルの一覧を確定してから、5 エージェントを並列に起動してください。
各エージェントには `CLAUDE.md` を読ませ、対象ファイルのパスを明示的に渡してください。

## 観点1: 正しさ

境界値、null と undefined、非同期処理の競合、例外の握り潰し、N+1 クエリを見る。
Drizzle のクエリでは、必要な結合の欠落、上限件数(`limit`)の付け忘れ、無条件の全件取得を確認する。
複数テーブルにまたがる更新が `db.batch()` にまとまっているかを見る。D1 に対話的トランザクションはない。

## 観点2: 設計と規約の遵守

- `src/domain/` が React にも Hono にも Drizzle にも依存していないか
- Drizzle の推論型がドメイン層やコンポーネントの引数に漏れていないか
- `any` の使用、戻り値の型の省略がないか
- 入力検証が Zod で行われ、画面と API で `src/shared/` の同じスキーマを使っているか
- Worker のコードで Node 固有の API(`fs`、ネイティブ `crypto`)を使っていないか
- コメントが日本語で書かれているか

## 観点3: 無料枠の制約

Workers 無料プランは 1 リクエストあたり CPU 10 ms、D1 は 1 日あたり読み 500 万行・書き 10 万行である。
超過は障害として現れ、運用費 0 円が要件のため有料プランへ逃げられない。

- Worker のハンドラで重い計算(集計、ソート、大量の整形)をしていないか
- 栄養値の算出とレシピ提案のスコア計算が Worker 側へ漏れていないか。どちらもブラウザ側で動かす
- 一覧取得に `limit` が付いているか
- 重い依存を足していないか。起動時間も CPU に算入される
- `public/data/*.json` を Worker のバンドルへ取り込んでいないか

## 観点4: セキュリティ

- 認証ミドルウェア(`requireUser`)の漏れ。クライアント側のルートガードだけで守っていないか
- 他人のデータへアクセスできる経路(`userId` による絞り込みの欠落)
- ユーザー入力が検証を経ずに DB とファイル名へ渡っていないか
- 秘密値のログ出力とクライアントへの露出

嗜好データのうち `ALLERGY` は安全に関わるため、除外ロジックの漏れを特に確認する。

## 観点5: テスト

分岐に対するテストの網羅、失敗経路のテスト、モックの過剰使用、壊れやすいアサーションを見る。

## 集約と報告

各エージェントの指摘を重大度で分類し、重複を除いて報告してください。

| 記号 | 意味 |
|---|---|
| 🔴 必須修正 | 不具合、セキュリティ問題、規約違反 |
| 🟡 推奨 | 設計上の改善、可読性 |
| 🟢 任意 | 好みの範囲 |

指摘は `ファイルパス:行番号` を添え、問題の内容と具体的な修正案を書いてください。
確認していない推測を、確認した事実として書かないでください。
